Haskellでつくる
3D描画の基盤

画面・影・水面の反射は、同じ世界を違う視点から描いています。その関係を純粋な値で定義し、描画のずれを直した事例を紹介します。

Stillroomは、作業中に音楽を流し、休憩中に風景を眺めるWindowsアプリです。描画にはHaskell、raylib、GLSLを使っています。

01 / 比較

動く車体と影のちらつきを直す

トロッコの表面と影が、移動中にちらついていました。0.10では、重複面、座標の丸め、描画ごとの地形と投影の違いを修正しています。下の映像は同じ場所・時刻・画質Highでの比較です。

形状

重複する面を取り除く

車体の寸法と配色を保ち、箱の接合部と二重の外面を除きます。同じ場所の二つの面が描画を競う状態をなくします。

精度

近い原点からの座標を使う

大きな世界座標から近傍の原点をDoubleで引き、そのあとFloatへ変換します。先に丸めて細部を失うのを防ぎます。

影

描く側と読む側をそろえる

地形を決める基準と投影を共有します。影の格子を光の方向に固定し、面の傾きを補正してから影を平滑化します。

02 / 設計

地形の選択と、描く視点を分ける

画面にはよく見える地面でも、影を描くときに別の形へ変わっていたら、影は合いません。従来は、描画に使うカメラが地形の細かさも決めていました。光や反射の視点に切り替わると、同じ地面の高さまで変わりえたのです。

新しい基盤では、形を決める基準と時刻を先に固定します。その世界を、人の目・光・水面越しの目がそれぞれ観測する。Haskellの純粋な値が、その共通の約束になります。

三つの観測はStillroom固有の構成です。共通部分はパス数を固定せず、別の用途では、その用途に合う形状の選択と観測を定義できます。

純粋関数の境界

描画計画を値として返す

現在の世界と、GPUが確保できた描画先の大きさを渡すと、planFrame が投影などをまとめた計画を返します。不正な入力にはエラーを返します。

この計算はGPUを操作しません。同じ入力から同じ計画が得られるので、ウィンドウを開かずに調べられます。実行前に、計画をGPUへ渡す形式に変換します。

座標の意味を型に残す

Transform Object Render は、車体の座標から描画用の座標への変換です。変換の接続先が合わない合成を、型検査で拒否します。

compose :: Transform b c
        -> Transform a b
        -> Transform a c
02

描画先と投影を一組に

影を描いたときの投影を、その影を読む側でも使います。Observation target が対応を保持し、C側でも描画画像と投影を一組にして渡します。

計画の内部を直接書き換える操作を公開せず、検証済みの対応を部分更新で壊せないようにしています。

03

GPUへの変換を一か所に

座標の計算はDouble、箱の接合はRational。最後に、有限なFloatだけを持つパケットへ変換します。

Cは資源の確保と描画を担います。Haskellの計画を受け取り、投影を別途計算し直しません。

03 / 形状の合成

箱を組み立ててから、外面を求める

隣り合う二つの箱を、それぞれ完成したメッシュとして足すと、接合部の面まで残ります。箱を組み立てたあとで外面を求めれば、隠れる面を初めから描かずに済みます。

部品の結合と、境界の抽出は順序を入れ替えられません。そこで、箱の集合と描画用のメッシュを別の型にしています。

対象は軸に沿った箱です。同じ外面に複数の材質が重なる場合は、後に置いた部品の材質を使います。

接合部は内側になるので、面を生成しません。

boundary (partsA ++ partsB)

箱の中央断面を模式化。実装では三次元の外面を求めます。

境界の計算には有理数を使う

車体の71個の箱をRationalで記述し、丸め誤差のない比較で739枚の外面へ整理します。車輪を合わせた1,798個の三角形は、一度生成して再利用します。

05 / 検証

型の外側も、実際の出力で確かめる

型で座標空間を区別しても、行列の成分やGPUへの転送まで自動で正しくなるわけではありません。性質テストと独立した参照計算に加え、実際に生成した頂点とGPUの出力を照合しました。

検証の範囲

これは有限のテストと特定GPUでの観測です。静的地形と植生には、遠い世界座標をFloatへ変換すると精度を失う経路が残っています。車体の結果を世界全体へ一般化はできません。数値、条件、残る制限は技術資料に記載しています。

Haskellが担う役割

見た目を改善したのは、形状・精度・影の具体的な修正です。Haskellでは、それらの計算を純粋な値と関数で表し、座標の取り違えや計画の部分更新を型と公開APIで防ぎます。GPUとの境界は、実際の出力を検証します。

この設計は他の言語でも実現できます。Stillroomでは、関数型の道具を使って関係をコードに残し、変更後にも確かめられる形にしました。独立した汎用エンジンへの切り出しは、今後の課題です。
