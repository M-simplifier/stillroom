ENGINEERING NOTES · STILLROOM 0.10 · 20 OCT 2026

同じ世界を、
矛盾なく描く。

形があり、光があり、それを眺める人がいる。
その関係をコードにも残すことで、
動く風景の落ち着きを取り戻しました。

ONE WORLD. DIFFERENT OBSERVATIONS.

Haskellで形と投影を決め、raylibとGLSLで描く。Stillroomの旅に組み込んだ、新しい描画基盤の記録です。

01 / THE VIEW

まず、動いているところを。

同じ湖畔、同じ時刻列、同じ画質High。境界を左右に動かすと、公開版0.9と今回の0.10を見比べられます。再生するまでは静止しています。

GEOMETRY

元の形を、重ねずに。

トロッコの寸法と配色はそのまま。重なる箱の内部と二重の外面を除き、ひとつの面にひとつの持ち主を与えました。

PRECISION

遠くへ進んでも、近い座標で。

車体とカメラの位置を高精度で引き算してからGPUへ。大きな世界座標を先に丸めることで生じる、細部の揺れを抑えます。

LIGHT

影も、同じ世界の観測。

形を決める視点と時刻を共有。影の格子を光の向きに固定し、面の傾きを考慮して影を比較・平滑化します。

02 / THE DESIGN

世界を決めることと、
世界を見ることを分ける。

画面にはよく見える地面でも、影を描くときに別の形へ変わっていたら、影は合いません。従来は、描画に使うカメラが地形の細かさも決めていました。光や反射の視点に切り替わると、同じ地面の高さまで変わりえたのです。

新しい基盤では、形を決める基準と時刻を先に固定します。その世界を、人の目・光・水面越しの目がそれぞれ観測する。Haskellの純粋な値が、その共通の約束になります。

THE PURE BOUNDARY

一瞬の描画計画を、ひとつの値に。

GPUが実際に用意できた描画先の大きさと、現在の世界を入力します。計画が成立したら、描画に渡せる形式へ変換します。

純粋な計画にはGPUハンドルも描画命令もありません。数値の整合性を、ウィンドウを開かずに調べられます。

01

座標の意味を型に残す

Transform Object Render は、車体の座標から描画用の座標への変換です。変換の接続先が合わない合成を、型検査で拒否します。

compose :: Transform b c
        -> Transform a b
        -> Transform a c
02

画像と、読むための写像を一組に

影を描いたときの投影を、その影を読む側でも使います。Observation target が対応を保持し、C側でも描画画像と投影を一組にして渡します。

検証済みの計画は、不透明な値として公開。外部から一部分だけを取り替える入口を閉じました。

03

GPUへの変換を一か所に

座標の計算はDouble、箱の接合はRational。最後に、有限なFloatだけを持つパケットへ変換します。

Cは資源の確保と描画を担います。Haskellの計画を受け取り、投影を別途計算し直しません。

03 / THE SHAPE

組み立ててから、外側を取り出す。

隣り合う二つの箱を、それぞれ完成したメッシュとして足すと、接合部の面まで残ります。箱を組み立てたあとで外面を求めれば、隠れる面を初めから描かずに済みます。

だから、この二つの操作は同じではありません。単に「合成できる」と言う前に、何を合成しているのかを型と構造で区別しました。

対象は軸に沿った箱の集合です。任意の曲面を処理する汎用CSGを名乗るものではありません。

接合部は内側になるので、面を生成しません。

boundary (partsA ++ partsB)

箱の中央断面を模式化。実装では三次元の外面を求めます。

EXACT UNTIL LOWERING

元の71個の箱をRationalで記述。境界の比較を丸めずに行い、739枚の外面へ整理。車輪を合わせた1,798個の三角形を、生成後に保持して使います。元の寸法や配色を変えて、ちらつきを隠す方法ではありません。

残る境界も、設計の一部に。

形式証明や、あらゆるGPU・経路での無欠陥を主張するものではありません。静的な地形や植生には、世界座標をFloatにしてから原点を引く従来の経路が残り、遠方を模した8対照点では最大0.03単位・主画面換算3.97ピクセルの誤差がありました。車体で確かめた精度を、世界全体へ一般化はできません。元の車輪の小さな隙間も保持しており、車体全体が水密な立体という意味でもありません。

WHAT CHANGED

関数型で、きれいになる。
その意味を、正確に。

画面を直接よくしたのは、幾何・精度・影の具体的な修正です。
Haskellで得たのは、それらの関係を一つの設計に置き、
次に変更するときも、整合性を守りやすくする基盤でした。

ほかの言語でも実現できる設計です。今回の価値は、純粋な値・型・合成・検証を、動く製品の描画までつなげられたことにあります。
